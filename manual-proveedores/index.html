2. Qué necesitamos, en una página

IMPRESCINDIBLE

  • Buscar productos por part number, marca o descripción.
  • Precio de nuestro nivel (sin IVA) y % de IVA.
  • Stock disponible por bodega (Guayaquil / Quito u otras), descontando lo reservado.
  • Consultar precio y stock de varios códigos a la vez.
  • Catálogo completo paginado para sincronizar.
  • Fecha y hora de la última actualización de cada dato.

MUY DESEABLE

  • Crear pedidos con nuestro número de referencia (sin duplicados).
  • Consultar estado del pedido y número de factura.
  • Promociones vigentes y unidades restantes a ese precio.
  • Peso con empaque (para cotizar flete) e imagen del producto.
  • Mercadería en tránsito con fecha estimada de llegada.
  • Una clave de pruebas que no cree pedidos reales.

3. Principios técnicos

TemaRecomendación
EstiloREST sobre HTTPS, respuestas en JSON UTF-8.
URL baseVersionada, por ejemplo https://api.su-empresa.com/api/v1. Cambios incompatibles → /v2.
Clave del productoEl part number del fabricante como codigo (es lo que cruzamos con nuestro ERP). Si usan código interno, inclúyanlo también como codigo_interno.
PreciosNúmeros decimales (no texto), sin IVA, en USD, con el nivel de precio del cliente dueño de la clave.
FechasISO 8601 con zona horaria: 2026-11-27T08:30:00-05:00.
FrescuraDatos actualizados al menos cada hora; campo actualizado en cada producto.
Paginaciónpage + limit, respuesta con total, pages, has_next.
CORS opcionalPermitir el encabezado X-API-Key facilita herramientas internas en el navegador. No es imprescindible si solo consultamos desde servidor.

4. Autenticación y límites

Una API key por cliente, enviada en el encabezado X-API-Key de cada consulta:

curl -H "X-API-Key: ck_su_clave" "https://api.su-empresa.com/api/v1/cuenta"
  • Vencimiento: la clave puede tener fecha de vencimiento, visible en GET /cuenta. Al vencer: 401 con mensaje claro.
  • Permisos separados: lectura (consultas) y escritura (pedidos). Idealmente, dos claves distintas.
  • Límite sugerido: 60 consultas por minuto; al superarlo, 429 con encabezado Retry-After.
  • Rotación: poder emitir una clave nueva y revocar la anterior sin cortar el servicio.

6. Endpoints

Método y rutaPara qué
GET/cuentareq.Cliente, RUC, nivel de precio, vencimiento de la clave, permisos y bodegas visibles.
GET/productos?q=req.Búsqueda por código, nombre, marca o categoría. Parámetros: q, solo_disponibles, page, limit (máx. 100).
GET/productos/{codigo}desea.Ficha completa: descripción técnica, imágenes adicionales.
POST/stock/bulkreq.Precio y stock de hasta 200 códigos. Códigos inexistentes con "encontrado": false (no error).
GET/catalogoreq.Todo el inventario paginado (hasta 500 por página). Ideal: actualizado_desde para traer solo lo que cambió.
GET/categoriasdesea.Categorías y marcas con cantidad de productos.
GET/direccionesdesea.Nuestras direcciones de entrega registradas.
POST/ordenesdesea.Crear pedido (ver sección 7).
GET/ordenes/{referencia}desea.Estado del pedido, factura y guía.
GET/ordenes?dias=30desea.Pedidos recientes.

→ { "productos": [ ... ], "total": 12, "page": 1, "limit": 20, "pages": 1, "has_next": false }

POST /api/v1/stock/bulk
{ "codigos": ["ABC123XYZ", "DEF456", "NOEXISTE"] }
→ { "resultados": [ { "encontrado": true, "codigo": "ABC123XYZ", ... },

7. Creación de pedidos

POST/ordenes registra un pedido igual que una compra en su web: lo procesa su asesor y se factura a nuestro nombre.

CampoDescripción
referenciaNuestro número de pedido (único). Si se reenvía la misma referencia —por ejemplo, tras un corte de conexión— se devuelve la misma orden con "repetida": true; nunca se duplica.
items[]codigo, cantidad y opcional precio_esperado: si el precio actual es mayor, se rechaza con 409 e informa el precio nuevo.
entrega.tiporetiro_gye · retiro_uio · envio (con direccion_id) · dropshipping (opcional: despacho directo a nuestro cliente con nuestra guía).
notaTexto libre (por ejemplo, quién retira), hasta 200 caracteres.
POST /api/v1/ordenes
{
  "referencia": "TS-261127-0915",
  "items": [ { "codigo": "ABC123XYZ", "cantidad": 2, "precio_esperado": 512.00 } ],
  "entrega": { "tipo": "retiro_gye" },
  "nota": "Retira Juan Pérez, C.I. 0900000000"
}

201 Created
{ "referencia": "TS-261127-0915", "orden": "1500001", "estado": "registrada", "repetida": false,
  "items": [ { "codigo": "ABC123XYZ", "cantidad": 2, "precio": 512.00 } ],
  "subtotal": 1024.00, "iva_estimado": 153.60, "total_estimado": 1177.60 }

Estados sugeridos

EstadoSignificado
registradaRecibida, en preparación.
retenidaEn revisión de crédito o cobranza.
facturadaFacturada; estado_detalle con el número de factura.
despachadaSalió de bodega; con fecha y número de guía.
anuladaNo se despachará.

8. Errores

Siempre con un JSON {"detail": "mensaje claro en español"}:

CódigoCuándo
401Falta la clave, es incorrecta, está desactivada o venció (el mensaje dice cuál).
403La clave no tiene permiso para esa acción (por ejemplo, crear pedidos).
404El producto o pedido no existe.
409Sin stock suficiente o el precio cambió (el detalle indica disponible/precio actual).
422Datos inválidos (el detalle indica qué campo).
429Superó el límite de consultas; reintentar luego de Retry-After.
500 / 502Error temporal; se puede reintentar.

9. Seguridad y pruebas

  • Clave de pruebas (sandbox): mismos datos de consulta, pero POST /ordenes responde como si creara el pedido sin crearlo realmente. Nos permite probar sin riesgo.
  • Claves separadas para lectura y para pedidos; revocables de inmediato.
  • Lista de IPs permitidas opcional: podemos darles la IP fija de nuestro servidor.
  • Registro de auditoría: qué clave hizo qué y cuándo, sobre todo en pedidos.
  • Nunca enviar claves por chat abierto: preferible un enlace de un solo uso o el portal del cliente.
Importante: los precios que expone la API son costos de distribuidor. Tecnosmart se compromete a no mostrarlos al público.

  • API key de pruebas y API key de producción (con su fecha de vencimiento).

12. Pruebas de aceptación

Con estos comandos ambos equipos pueden verificar que la conexión funciona. Reemplace la URL y la clave.

BASE="https://api.su-empresa.com/api/v1"; KEY="ck_clave_de_pruebas"

# 1. La clave funciona y muestra nivel de precio y vencimiento
curl -s -H "X-API-Key: $KEY" "$BASE/cuenta"

# 2. Búsqueda por part number y por descripción
curl -s -H "X-API-Key: $KEY" "$BASE/productos?q=ABC123XYZ"
curl -s -H "X-API-Key: $KEY" "$BASE/productos?q=notebook%20ryzen&solo_disponibles=true"

# 3. Stock de varios códigos (uno inexistente no debe dar error)
curl -s -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"codigos":["ABC123XYZ","NOEXISTE"]}' "$BASE/stock/bulk"

# 4. Catálogo paginado
curl -s -H "X-API-Key: $KEY" "$BASE/catalogo?limit=500&page=1"

# 5. Pedido en sandbox, enviado DOS veces: la segunda debe responder "repetida": true
curl -s -X POST -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"referencia":"PRUEBA-001","items":[{"codigo":"ABC123XYZ","cantidad":1}],"entrega":{"tipo":"retiro_gye"}}' \
  "$BASE/ordenes"

# 6. Clave inválida → 401 con mensaje claro
curl -s -H "X-API-Key: ck_invalida" "$BASE/cuenta"
  • Todas las respuestas son JSON con tildes correctas (UTF-8).
  • El precio coincide con el de su portal web para nuestro nivel.
  • El stock disponible descuenta lo reservado.
  • Reenviar un pedido con la misma referencia no lo duplica.
  • Superar 60 consultas por minuto devuelve 429.
